## 这是什么？

莫顿教学系统（tms-mx.xueqiulearning.com）里创建一道选择题，需要手动填题干、排画布、设反馈……一道题就要花几分钟。如果一次要导入 50 道题，工作量巨大。

**这个工具做什么？**

1. 你在 Excel 里写好 N 道题（2~8 个选项，支持文本/图片/音频反馈）
2. 把莫顿 Cookie 粘贴到工具里验证身份
3. 上传 Excel → **CSS 布局预览**每道题的画布效果 → 点「批量生成」
4. 自动把 N 道题全部创建好，包括智能画布排版、通用反馈、条件反馈
5. 生成成功后 → **Playwright 真实截图预览**，100% 还原莫顿实际效果

**省多少时间？** 原来 50 题手动操作约 2 小时，现在约 3 分钟。

**项目规模：** Python + HTML/CSS/JS + Node.js，82 个自动化测试，11 个功能模块。

## 使用流程（图文）

### 步骤 1：获取并粘贴 Cookie

1. 浏览器打开莫顿教学系统，登录
2. 按 `F12` → `Application` → `Cookies` → 复制 `tokenCrm` 的值

> 如果找不到，可以把整个 Cookie 字符串全部复制粘贴进去，工具会自动提取 tokenCrm。

3. 粘贴到工具页面的输入框，点击「验证 Cookie」
4. 验证成功后会显示「Token 有效期至 XX」、操作者 ID

### 步骤 2：上传 Excel

点击「选择 Excel 文件（可多选）」或拖拽 `.xlsx` 文件到上传区域。可一次选多个文件，每个文件会解析后在独立标签页中显示。

### 步骤 3：配置全局默认值（可选）

如果你的 Excel 里有些题目没填学科/年级/阶段/难度，可以在「全局默认设置」区域下拉选择，空缺的题目会自动使用这些值。

### 步骤 4：预览 → 批量生成

预览表会显示所有解析出的题目，每道题有两种预览方式：

- 🟢 **布局预览**（绿色按钮）：解析后即可点击，用 CSS 本地渲染查看画布布局和选项位置，确认坐标排版是否正确
- 🔵 **📸 真实预览**（蓝色按钮）：生成成功后出现，调用 Playwright 打开莫顿页面截图，100% 还原真实效果（背景图、样式、文字渲染完全一致）

> 推荐流程：先用「布局预览」确认坐标 → 批量生成 → 再用「📸 真实预览」确认最终效果

然后：
- 点「**批量生成**」：只生成当前标签页的题目
- 点「**全部生成**」：按顺序生成所有文件的题目（自动切换标签页）

进度条会实时显示每道题的生成状态。

### 步骤 5：生成完成

进度条走完后，每道题的生成结果显示在表格里（✅ 成功 / ❌ 失败）。失败的可以查看原因。

> 生成结果按文件独立保存，切换标签页后仍然显示，不会消失。

### 步骤 6：清空，上传新表格

点「清空全部」按钮，所有文件数据重置，直接上传下一批 Excel。

## 功能说明

### 功能 1 — 智能画布布局引擎（4 阶段核心逻辑）

每道题上传到莫顿时，布局引擎自动计算画布上所有元素的位置。核心算法 `_calculate_smart_layout()` 采用四阶段设计，前后端共享同一套逻辑：

**布局对象：题目文本 + 题目图片 + 选项框 + 画布背景**

```
阶段 1 → MEASURE（测量）：逐字精确测量每个元素像素尺寸
         ├── 中文 width = font_size × 0.85
         ├── 英文/数字 width = font_size × 0.55
         ├── 标点 width = font_size × 0.40
         └── 图片等比例缩放到 max 45%绿框宽 × 35%绿框高

阶段 2 → PARTITION（分区）：根据内容组合划分绿框空间
         ├── 无图片 → TEXT_ONLY：全宽文本，选项下方
         ├── 单图+短文本 → IMAGE_LEFT_TEXT_RIGHT：图文并排
         └── 多图/长文本 → IMAGE_TOP_TEXT_BELOW：图片上方，文本居中在下方

阶段 3 → PLACE（放置）：在各自分区内放置元素
         ├── 文本按可用宽度逐字换行，行内居中
         ├── 图片水平居中对齐，间距 MIN_GAP
         └── 选项均匀分布，宽度/高度自适应

阶段 4 → ADJUST（微调）：防止越界，保证最小间距，优化美感
```

- **画布尺寸**：默认 1334×750（可用 Excel「分辨率」列修改）
- **内容区域（绿框）**：x=182~1152（宽 970），y=130~580（高 450）
- **字号自适应**：总字符数 ≤15→50px, ≤40→45px, >40→40px
- **选项框动态尺寸**：2选项 220px宽间距 180+, 3选项 210px宽间距 80+, 4选项 190px宽间距 50
- **文本逐字换行**：超绿框宽度时在字符边界换行，中文标点不出现行首

### 功能 2 — 通用反馈

「答错反馈」和「答对反馈」支持文字、图片、音频三种形式：
- 每个题目可以单独配置（在 Expo 中设置 → 预览表点「编辑」按钮 → 弹窗填写）
- 也可以在页面「全局反馈默认值」统一设置，所有题目共享
- 弹窗里还能配置**条件反馈**（见功能 3）

### 功能 3 — 条件反馈（基于错误次数）

条件反馈是什么？举个例子：

> 学生做错了 **第 1 次**：显示 "再试一次！"
> 学生做错了 **第 2~3 次**：显示 "提示：答案是两位数"
> 学生做错了 **第 4 次以上**：显示 "正确答案是 XX，记住哦！"

在预览表的「编辑」弹窗里，可以添加多条条件反馈，每条设置：
- **触发条件**：错误次数区间（如 2~3 次）
- **反馈内容**：文字 / 图片 / 音频

> ⚠️ 当前仅支持「错误次数（WrongNumber）」这一个条件变量。

### 功能 4 — 自动重试

莫顿服务器偶尔会返回 500 错误或超时。工具会自动重试：
- **最多重试 2 次**（总共 3 次尝试）
- **间隔 1 秒**后重试
- 只有 5xx 和超时才会重试，4xx（客户端错误）不重试（重试也没用）
- 控制台会打印 `[RETRY]` 日志

### 功能 5 — Token 过期检测

莫顿的登录 Cookie（tokenCrm）是 JWT 格式，里面有一个 `exp`（过期时间）字段。

工具会：
1. **验证 Cookie 时**：告诉你"有效期至 XX"、"已过期"、或"N 分钟后过期"
2. **批量生成前**：自动检查，如果过期直接拒绝生成（避免生成到一半失效）
3. **10 分钟内过期**：弹出提示，问你是否继续

### 功能 6 — 空值友好显示

预览表中，如果某题的学科/年级/阶段/难度为空（值为 0），显示 `未设置` 而不是 `0`。

### 功能 7 — SSE 实时进度条（batch-create-stream）

批量生成时，不再是"点了按钮等半天不知道进度"。基于 Server-Sent Events 实现：

- 连接建立时立即发送 `{total, progress:'0/N', percent:0}` 初始事件
- 每道题生成完立刻推送 `{index, success, questionId, progress, percent}` 事件
- 前端逐条接收、逐条渲染：**生成结果列**显示 ✅ #题号（成功）或 ❌ 错误原因（失败）
- **操作列始终保留「编辑反馈」按钮**，生成成功后仍可随时修改反馈
- **进度条**实时显示百分比（如 `3/50（6%）`），完成后显示 `✅ 完成`
- **切换标签页时，生成结果和进度条按文件独立保存**，不会消失
- 全部完成后发送 `{done:true, successCount, failCount}` 完成事件
- 响应头：`Cache-Control: no-cache`、`Connection: keep-alive`、`X-Accel-Buffering: no`（兼容反向代理）

### 功能 8 — 浏览器缓存已禁用

服务端设置了 `Cache-Control: no-cache, no-store, must-revalidate`，浏览器不会缓存页面。更新代码后直接刷新即可看到最新版，不用 `Ctrl+F5` 强制刷新。

### 功能 9 — 分级清空

预览表底部提供四个按钮：
- **批量生成**（绿色）：只生成当前标签页的题目
- **全部生成**（紫色）：按顺序生成所有文件的题目（自动切换标签页）
- **清空当前**（橙色）：只清空当前标签页的文件，其他文件保留
- **清空全部**（红色）：一次性清除所有文件，恢复到初始状态

### 功能 10 — 多文件导入 + 分标签页

支持一次选择多个 Excel 文件（文件输入框可多选或逐个添加）：

- 每个文件独立解析，显示在各自的标签页中
- 标签栏显示文件名 + 题目数量
- 点击标签切换，每个文件独立预览、编辑反馈、批量生成
- **生成结果和进度条按文件独立保存**，切换标签后恢复显示
- 同名文件自动替换（方便修改 Excel 后重新导入）
- 只有 1 个文件时不显示标签栏（与之前体验一致）

### 功能 11 — 题目预览（双模式）

每道题的操作列都有预览按钮，根据题目是否已生成，提供两种预览方式：

**生成前 → 布局预览（绿色按钮）**
- 解析完 Excel 即可查看，不需要先上传到莫顿
- 用和后端同一套 `_calculate_smart_layout` 算法计算坐标，在前端用 CSS 绝对定位还原画布
- 坐标、大小、布局与莫顿完全一致；字体和换行可能有细微差异
- 正确答案的选项框右下角会显示小红点
- 画布按 0.5 倍缩放（667×375），米黄色画布 + 绿色虚线边框
- ⚠️ 标注为「布局参考」，不支持背景图等复杂元素

**生成后 → 📸 真实预览（蓝色按钮）**
- 题目成功生成后，按钮自动切换为「📸 真实预览」
- 后端调用 Playwright（Node.js）打开莫顿真实页面，自动截图返回
- **100% 还原**：背景图、选项样式、文字渲染、条件反馈等全部元素与莫顿完全一致
- 首次截图约 5~10 秒，后续访问走缓存（10 分钟内秒返回）
- 截图服务需要安装 Node.js 依赖：`npm install`（使用系统 Chrome，无需下载 Chromium）
- 如果未安装 Node.js 依赖，截图预览不可用，但布局预览和所有其他功能不受影响

> 推荐流程：先用「布局预览」确认坐标布局 → 生成 → 再用「📸 真实预览」确认最终效果

## 莫顿编号改了怎么办？

莫顿系统可能会调整学科/年级/阶段的内部数字编号（比如「数学」从 ID=4 改成 ID=99）。如果硬编码在代码里，就要到处找出来改，容易遗漏。

**本项目的解决方案：**

所有映射数据集中在 **唯一一个文件** `config/mappings.yaml`：

```yaml
# 莫顿改编号时，只需改这一个文件！
subjects:
  数学: 4       # ← 如果莫顿把数学改成99，这里改成 数学: 99 即可
  英语: 13
  新数学: 14
  思维盒子: 18

grades:
  幼儿-小班: 9
  # ... 省略
  高三: 16

stages:
  春: 2
  暑: 3
  # ... 省略

difficulties:
  简单: 1
  中等: 3
  困难: 5
  # ... 省略
```

**数据流动：**

```
config/mappings.yaml（你手动改这里）
    ↓ 服务启动时自动加载
后端 config/__init__.py
    ↓ 前端请求 GET /api/metadata/mappings
前端 index.html
    ├── 下拉框的选项自动更新（学科、年级、阶段、难度）
    └── 预览表的中文名自动更新（ID → 中文名反查）
```

**操作步骤：**

1. 打开 `config/mappings.yaml`，修改编号
2. 重启服务（关掉 `python main.py` 再启动）
3. 刷新浏览器页面
4. 前后端就自动同步了 —— 不需要改任何代码

**验证修改是否正确：**

```bash
cd "C:/Users/XQ/Desktop/question-factory"
python -m pytest tests/test_mappings.py -v
```

## 常见问题 & 已知限制

### ❓ 上传 Excel 后预览表没出来

1. 检查表头是不是 31 列、顺序对不对
2. 打开浏览器 F12 → Console 看有没有报错
3. 确认学科/年级/阶段的名字和 mappings.yaml 里一致

### ❓ 批量生成到一半报"Token 过期"

1. 回到莫顿系统，重新登录
2. F12 → Application → Cookies → 复制 tokenCrm
3. 粘贴到工具的 Cookie 输入框，重新验证
4. 之前在 token 有效期间生成的题目不会丢失

### ❓ 选项太少/太多

支持 **2~8 个选项**。选项 C~H 可以为空，有多少就显示多少。

### ❓ 图片/音频怎么加

图片和音频需要先在莫顿系统中手动上传，获取 URL 后，填到 Excel 的对应列（K~N 列），或在预览表的编辑弹窗里填写。

### 已知限制

| 限制 | 说明 | 影响 |
|------|------|------|
| 映射表需人工维护 | 莫顿没有开放 API 获取学科/年级列表，编号变了需要手动改 mappings.yaml | 低 |
| 条件反馈仅支持「错误次数」 | 不支持按"正确次数""答题时间"等条件触发 | 低 |
| 极多文本(>10段)可能超出绿框 | 画布智能排版在极多文本时可能估算不准 | 极低 |
| 批量生成端到端测试缺失 | 86 个测试覆盖了各子模块，但缺少模拟完整流程的集成测试 | 低 |
| 截图需登录态 | 真实预览依赖 Cookie 有效，过期后截图会失败 | 低 |
| 截图需系统 Chrome | Playwright 调用本地 Chrome，未安装则截图不可用 | 低 |

## 待解决问题

### 安全性（优先级：中）

当前 Cookie 明文存储在浏览器 localStorage 中，如果电脑被他人使用，Cookie 可能泄露。

**建议方案：**
- Cookie 只在服务端内存中保存，前端只拿一个会话 ID
- 或者至少对 localStorage 中的 Cookie 做简单加密

### 条件反馈扩展（优先级：低）

当前条件反馈只支持「错误次数（WrongNumber）」这一个触发变量。如果莫顿支持更多变量（如正确次数 RightNumber、答题耗时 TimeSpent），可以扩展。

**待确认：** 莫顿系统具体支持哪些条件变量？需要从 F12 抓包确认。

### 后端 API（8 个端点）

| 路径 | 方法 | 用途 |
|------|------|------|
| `/` | GET | 首页（index.html），禁用缓存 |
| `/static/{filename}` | GET | 静态文件服务，禁用缓存 |
| `/api/auth/validate` | POST | 验证 Cookie，解析 JWT，返回 Token 过期时间和操作者 ID |
| `/api/question/parse-excel` | POST | 上传并解析 .xlsx，返回题目列表（含学科/年级/阶段/难度映射） |
| `/api/question/batch-create-stream` | POST | **SSE 流式**批量创建，实时推送每道题的生成进度 |
| `/api/question/batch-create` | POST | 普通批量创建（一次性返回全部结果，备用） |
| `/api/question/preview-payload` | POST | 构建题目完整 payload（含布局坐标），供前端 CSS 预览使用 |
| `/api/question/preview-create` | POST | 在莫顿创建一条带 `【预览-可删除】` 前缀的预览题 |

| `/api/screenshot/health` | GET | 检查截图服务是否就绪（Node/脚本/playwright模块） |

### 莫顿 API（被调用的）

| 接口 | 用途 |
|------|------|
| `POST /merton-backend/question/insert` | 创建题目 |
| `POST /merton-backend/question/update` | 写入元数据 + 通用反馈 + 条件反馈 |

> 两个接口原本需要分别调用，本工具合并为一次 update 调用，减少一半网络请求。

### 核心实现细节

```python
# ══════ 智能画布布局引擎 — 4 阶段核心逻辑 ══════
# 阶段 1  MEASURE: 逐字精确测量每个元素的渲染像素尺寸
#   字符宽度系数: 中文 0.85×字号, 英文 0.55×字号, 标点 0.40×字号
#   行高 = 1.35×字号
#   _measure_paragraph() → 返回 {lines, max_line_width, total_height}
#
# 阶段 2  PARTITION: 根据内容组合划分绿框空间
#   TEXT_ONLY        — 无图片, 全宽文本
#   IMAGE_LEFT_TEXT_RIGHT — 单图, 图文并排
#   IMAGE_TOP_TEXT_BELOW  — 多图, 图片上方+文本居中下方
#
# 阶段 3  PLACE: 在各自分区内放置元素
#   文本逐字换行, 超绿框宽度时在字符边界断行
#   中文标点不出现行首, 挂在上一行末尾
#   图片等比例缩放 (max 45%宽 × 35%高)
#
# 阶段 4  ADJUST: 微调防止越界, 保证 MIN_GAP 最小间距

# ===== 难度解析：支持数字和文本，范围限制 0~5 =====
difficulty_raw = str(row[16] or "").strip()    # Excel 第 Q 列
if difficulty_raw.isdigit():
    difficulty = max(0, min(5, int(difficulty_raw)))
else:
    difficulty = DIFFICULTY_MAP.get(difficulty_raw, 0)

# ===== 年级文本自动处理全角破折号 =====
grade = str(row[14] or "").strip().replace("－", "-")

# ===== 合并 update：一次 API 调用写入元数据 + 通用反馈 + 条件反馈 =====
# 原本：/insert → /update(元数据) → /update(反馈) 三次调用
# 现在：/insert → /update(全部) 两次调用，减少 33% 网络请求

# ===== Playwright 截图架构 =====
# Python 无法编译 greenlet → 改用 Node.js Playwright
# Python 后端 → 子进程调用 screenshot.js → stdout 接收 PNG
# 系统 Chrome 优先, 无需下载 Chromium (300MB)
# 缓存：10 分钟 TTL, MD5(questionId+cookie) 做 key
# 并发锁：asyncio.Lock 防止同时启动多个浏览器实例

# ===== SSE 流式推送 =====
# 连接建立时发送初始事件 {total, progress:'0/N', percent:0}
# 每道题生成完推送 {index, success, questionId, progress, percent}
# 全部完成后发送 {done:true, successCount, failCount}
```
